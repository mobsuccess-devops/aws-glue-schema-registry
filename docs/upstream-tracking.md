# Upstream tracking

Every open issue and pull request on
[`awslabs/aws-glue-schema-registry`](https://github.com/awslabs/aws-glue-schema-registry),
and how this fork relates to each. Upstream has been dormant since `eed1506` (2026-08-13) —
the fork point, and still its `master` HEAD — so its open queue is the closest thing the two
repositories have to a shared backlog. This file records what remains to adopt, what the fork
has shipped, and what it deliberately leaves aside — one section per status, most actionable
first.

- **[To address](#to-address)** — worth adopting. Every row carries a triage verdict:
  _planned (S/M)_ when the approach is settled (S ≈ under a day, M ≈ days), _spike_ when a
  design question or reproduction must come first, _deferred_ when blocked on another
  decision, _evaluate_ when the first triage pass could not settle it.
- **[Addressed](#addressed)** — shipped in this fork; the note links the pull request or
  names the coverage.
- **[Out of scope](#out-of-scope)** — deliberately not pursued, with the reason. "C#", "Go"
  and "native" refer to the multi-language layer this fork removed.

Last sync: 2026-09-03 — upstream `master` is still `eed1506` (no commit since 2026-08-13),
but three pull requests opened there on 2026-09-01/02 are folded in below: #537 (HTTP-client
injection), #538 (SDK v1 removal) and #539 (Kafka 3.9.2 for CVE-2026-35554, whose description
mentions an internal "GSR Client Library 2.0.0 security release" — the first sign of upstream
activity since the fork point). Triage pass of 2026-08-21: every open upstream thread was read
against the fork's current code; verdicts below reflect that review. Move the relevant row
when a fork pull request lands on one of these items; re-sync the whole inventory when
upstream moves.
